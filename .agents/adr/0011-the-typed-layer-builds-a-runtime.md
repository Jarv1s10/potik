# The typed layer builds a Runtime, and middleware instances are used once

The typed layer has no App. `potik.build_runtime(config, routers, ...)` compiles routers, the run's context, middleware, and exception rules into a core `Runtime`. That runtime runs once and provides `status()`, as Starlette sits under FastAPI. A service builds its resources with `async with` in its own `main`, then builds the runtime. So middleware takes the run's resources in `__init__`, and a second run is a second call of `main`. Runtimes and producers take middleware instances. Entering an instance a second time raises, because a middleware's lifespan keeps state about its owner, e.g. tracing's client ids. A `Producer` is entered once, and a web service opens it in its framework's lifespan. Routers have no middleware. A per-topic exception rule takes `on(..., topics=...)`, and other per-topic behavior checks `record.topic()` in the runtime's middleware. The exception rules keep their fixed position inside the runtime's middleware.

We rejected an App object declared at import time, as in FastAPI. It built its middleware before the resources that application middleware needs existed. It took `Middleware` specs to rebuild instances per run, and a lifespan context for handlers to reach resources, and middleware still could not reach them. We rejected factories of the lifespan context, which kept two ways to pass middleware. We rejected a typed state store on the run, like aiohttp's `AppKey`, which keeps specs and adds keys. Removing router middleware removes the only place for middleware inside the exception rules, e.g. a timeout for each retry attempt. Handlers or dependencies do that instead.
