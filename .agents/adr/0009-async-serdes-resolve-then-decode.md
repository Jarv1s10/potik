# An async serde resolves a sync decoder per record

A serde whose decoding needs I/O, e.g. a schema registry's, is an `AsyncSerde`. For each type it returns a resolver: an async function that does one record's I/O and returns the sync decoder of that record. potik lets the resolver's failures propagate as they are, so `retry()` rules retry e.g. a timeout, and wraps the decoder's failures in a permanent `DecodeError`, as it does for every `Serde`. The split itself tells a transient failure from a permanent one, so a serde author has nothing to remember.

We rejected a plain async decoder. potik would then need the serde to classify its own failures. If potik wrapped every failure in `DecodeError` unless the serde marked it as I/O, a serde that forgot would dead-letter records during a registry outage. If potik let every failure propagate unless the serde marked it as permanent, a serde that forgot would retry an undecodable record forever and stick its partition under `retry_forever()`. A deterministic bug inside a resolver is still retried, but a resolver is small and mostly I/O. Encoders stay synchronous: an output's writer schema is fixed by its type, so its I/O does not depend on each record. potik gives serdes no lifespan, because a serde's client belongs to whoever creates it, as a Producer does (ADR 0001).
