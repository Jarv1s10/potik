# Three layers, each importing only the ones below it, checked by ruff

potik has three layers, like Starlette under FastAPI. The core runtime (`potik.core`) is the minimal wrapper around confluent-kafka: `Runtime`, `Producer`, `Config`, records, offset policies, status and its health probes, and the middleware protocol. The built-in middleware (`potik.middleware`) sits above it and imports only the core. The typed layer (`App`, `Router`, `Topic`, parameter markers, and serdes) sits at the package root above both. The core is usable without the layers above it, and has its own user docs page and reference section.

Each name has one home, where the reference documents it. The root `potik` re-exports the core names that an ordinary app writes, e.g. `Config`, `Producer`, `Middleware`, `OffsetContext`, and `RuntimeStatus`, as FastAPI re-exports Starlette's `Request`. Names for extending the runtime, e.g. `BaseMiddleware` and `RunScope`, come only from `potik.core`. `potik.middleware` re-exports nothing of the core's.

Nested `ruff.toml` files in `src/potik/core/` and `src/potik/middleware/` ban imports of the layers above with `banned-api` (TID251). Banning a module also bans its submodules and the relative imports that resolve to them. A name that the root re-exports, e.g. `from potik import Topic`, needs its own entry, because banning `potik` would also ban `potik.core`. A new typed name on the root must be added to both lists. Forgetting it lets only a function-level import through, because a module-level one fails as a circular import.

The health probes live in the core, because their thresholds restate the runtime's timing guarantees. The middleware stays out of the core, because AGENTS.md keeps the core minimal and ADR 0003 keeps policy, such as the topic check and concurrency limits, out of it. The typed layer keeps the root, because most users start from `from potik import App`.

Importing `potik.core` still runs `potik/__init__.py`, and so imports the typed layer, because Python imports a package's parents first. The independence is in what each layer may use, not in what loading it costs. We rejected separate distributions, e.g. a `potik-core` package in a uv workspace: they would also make loading independent, but at the cost of two versions and two releases, and the core would drop only the `typing-extensions` dependency. We rejected import-linter, which states layers directly, because ruff already runs on every change. We rejected putting the built-in middleware inside the core, and giving the core the root name.
