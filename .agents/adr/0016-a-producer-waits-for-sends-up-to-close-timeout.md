# A Producer waits for its sends up to a close timeout, then purges them

Leaving a `Producer` waits for every send's delivery report. During a broker outage, each report comes only after librdkafka's `message.timeout.ms`, 300 seconds by default, so the exit outlasted Kubernetes' 30 second termination grace period and ended in SIGKILL. A purge loses no more than the kill does, but the process exits on its own and reports the failed sends. So the exit now waits up to `close_timeout`, 10 seconds by default, then purges the queued and in-flight sends, which fail with `_PURGE_QUEUE` or `_PURGE_INFLIGHT`. A purged in-flight send may still be delivered, as a cancelled one may. The default leaves room for a run's shutdown before the producer's own, e.g. the final transaction, within the default grace period. This mirrors the Java client's `close(Duration)`.

We rejected a lower default `message.timeout.ms`. It would bound the exit as well, but every send would then fail during a hard broker failover, which takes about 9 seconds for KRaft's broker session to expire, plus the leader election. We also rejected documenting the limit alone, which leaves users with that same trade-off.
