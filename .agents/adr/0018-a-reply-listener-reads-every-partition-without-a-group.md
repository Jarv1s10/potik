# A reply listener reads every partition of the reply topic, without a group

A request-reply caller, e.g. an API with many replicas, awaits each reply in the process that sent the request. A shared consumer group hands each partition of the reply topic to one replica, so with N replicas about (N-1)/N of the replies reach a replica that does not await them, and the request times out. So `ReplyListener` reads every partition itself, with a consumer that never joins a group or commits, from the end offsets read when it opens, and drops the replies that it does not await. `Runtime` does not serve this. Its group membership, committed offsets, and replay safety all assume that any member may handle any record, and a reply has exactly one process that can use it.

We rejected a reply partition per replica, sent in a header for the responder to honour, as Spring's `ReplyingKafkaTemplate` allows. It needs a stable replica number, e.g. from a StatefulSet, and at least as many partitions as replicas, so it breaks under autoscaling. We rejected a reply topic per replica, whose topics outlive their replicas. We rejected a consumer group per replica, which would assign new partitions without polling metadata, because `auto.offset.reset=latest` resolves a partition's start only at its first fetch, after which a reply to an early request may already sit. We also rejected forwarding replies from a shared group to the awaiting replica through e.g. Redis pub/sub, which adds a second system and its own ordering race. Broadcasting costs each replica one `correlate` call per reply to another replica, which is small at the rates that request-reply serves.

The listener does not send requests and sets no correlation convention, e.g. a `correlation-id` header. Apps already carry IDs in headers, in values, or through other systems, e.g. an HTTP call that makes a service reply to Kafka, and a built-in header would be one more contract that responders must honour. The app sends `PendingReply.correlation_id` however its responder reads it, and passes `correlate` to read it back.
