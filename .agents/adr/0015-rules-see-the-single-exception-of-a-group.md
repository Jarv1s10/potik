# Exception rules see the single exception of a group

A handler that runs a task group raises an `ExceptionGroup`, even when only one task failed, because anyio and asyncio cancel the other tasks and leave their cancellations out of the group. Rules match like `except` clauses, so `on(TimeoutError, retry(...))` never matched a timeout from a task group, and the partition stopped. `ExceptionMiddleware` now gives the rules the exception of a group that holds exactly one, through any nesting. Its `PermanentError` check and dead letter headers then see the real failure too. A group of several exceptions stays a group, which `on(ExceptionGroup, ...)` or a function matches, and an exception that no rule handles propagates as the handler raised it, with its traceback.

We rejected `except*`-style matching, where a rule matches a group when every exception in it matches. A rule decides for the whole record, so it would get the group as `ExceptionContext.exception`, which `on()` types as the matched exception, e.g. a `TimeoutError`. We also rejected leaving unwrapping to users, because the common case, one failed task, would otherwise need a predicate in every service that uses task groups.
