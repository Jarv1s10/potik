# `potik.testing` handles one record without Kafka

Amends [ADR 0005](0005-test-apps-on-librdkafkas-mock-cluster.md), which removed `App.handle` because it put a test entry into the production API. `potik.testing.handle_record(runtime, record)` brings that capability back outside the production API: it runs one record through a built `Runtime`'s `handle` stage, i.e. its middleware, exception rules, concurrency limits, handler, and output check, and returns the outputs. A test of a handler's decoding, dependencies, rules, and outputs then needs neither a cluster nor a task group, and potik's own tests stop reaching into the private `runtime._handler`. It takes a built runtime rather than routers, so a test runs the service's own build function, with its middleware, rules, and context.

It is not a substitute for `MockCluster`, and ADR 0005's reasoning still holds for what it leaves out: lifespans, the topic check, transactions, key ordering, partition stopping, and rebalances. An exception that no rule handles propagates, which a run would turn into a stopped partition. We rejected a public method on `Runtime` for the same reason ADR 0005 removed `App.handle`, and a function of routers, which would duplicate `build_runtime()`'s arguments and test a pipeline that the service never runs.
